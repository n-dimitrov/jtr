Jira for you, and for your coding agent.

One local CLI for Jira Server, Data Center and Cloud. You use it from the terminal. Your coding agent uses it through a shared skill. Reads are free. Every write is previewed, needs your approval, and is logged.

  • Claude Code
  • Codex
  • Gemini CLI
  • Copilot
  • Cursor
  • OpenCode

Why a skill, not another integration

  • Your agent already knows Jira. Ask "what's assigned to me?" or "move PROJ-123 to In Progress" in the chat you have open. No MCP server to run, no API key pasted into an agent config.
  • Writes are gated. The skill tells the agent to show every change first and never pass --yes unasked. The CLI previews, confirms and audits the same way, so the agent can't do more than you could.
  • One file, every agent. The same SKILL.md installs into whichever agent you use, and jtr update keeps every copy fresh.

1Install

One command. It installs uv if you don't have it, then installs jtr.

$ curl -LsSf https://n-dimitrov.github.io/jtr/install.sh | sh
> irm https://n-dimitrov.github.io/jtr/install.ps1 | iex

If jtr isn't found afterwards, open a new terminal.

Run it in PowerShell. If jtr isn't found afterwards, open a new terminal.

Install without the one-liner (offline or restricted network)
  1. Download Source code (zip) from the latest release and extract it.
  2. Run the bundled installer from the extracted folder: ./install.sh on macOS and Linux, or powershell -ExecutionPolicy Bypass -File .\install.ps1 on Windows.

To pin a version with the one-liner, set JTR_VERSION first, for example JTR_VERSION=1.2.0. More in INSTALL.md.

2Connect to your Jira

Run this in your project folder with the URL of any ticket. It saves the Jira address and project, logs you in, and installs the /jtr skill for that project. In a terminal it asks which agent should get the skill; Claude Code is the default.

$ jtr init --ticket https://tracker.example.com/jira/browse/PROJ-123 --auth sso
  • Server / Data Center: --auth sso for a browser login, or --auth pat for a Personal Access Token.
  • Cloud: jtr init --base-url https://your-tenant.atlassian.net, then jtr auth token.
$ jtr whoami
$ jtr list mine
$ jtr view PROJ-123

3Use it from your coding agent

you    move PROJ-123 to In Progress
agent  PROJ-123  Fix login redirect   Open → In Progress
       I'll run: jtr transition PROJ-123 "In Progress"
       Go ahead?  waiting for your ok
you    yes
agent  Done. Audit: transition PROJ-123 → In Progress  ok:true

The /jtr skill is one SKILL.md that every agent below can read. jtr init installs it for the agent you pick. jtr skill install adds it anywhere else, and asks the same question when you leave out --agent.

$ jtr skill install --agent claude           # this project
$ jtr skill install --agent claude --global  # every project

jtr skill status shows where the skill is installed and whether each copy is current. jtr skill update refreshes every copy, for every agent.

↻Update

Updates jtr to the latest release and refreshes every installed copy of the skill, whichever agents you use. A skill file you have edited yourself is never overwritten.

$ jtr update
> irm https://n-dimitrov.github.io/jtr/install.ps1 | iex

Only want to know if there is a newer release? jtr update --check

On Windows a running program can't replace itself, so updating means re-running the installer. jtr update --check tells you whether there is a newer release.

Uninstall: uv tool uninstall jtr
